# 입사 D-7, 우리 팀의 AX 작전

신입사원 30명의 온보딩을 준비하는 교육팀 이야기. 플레이어는 팀에 합류한 지 얼마 안 됐지만 AI를 잘 쓰는 **윤진 매니저**가 되어, **방향키로 사무실·회의실·자료실·팀장실·라운지를 돌아다니며** 팀원에게 다가가 이야기를 듣고(가까이 가면 음성+말풍선), 자리 PC에 앉아 업무를 배치하고 AI 흐름을 구성하고 산출물을 공유합니다.

> 중심 질문: 제한된 환경에서 성향과 강점이 다른 팀원들이 AI를 어떻게 나누어 쓰고, 결과를 검증하고, 다른 사람이 다시 쓸 수 있게 남길 것인가?

AI를 많이 쓰면 이기는 게임이 아닙니다. 세 줄 수정은 사람이 직접 하는 편이 낫고, 300건 분석은 AI 초안 + 원문 확인이 낫고, 조건이 많은 도구는 요구사항 정리가 도움이 됩니다. 모든 선택은 비용·산출물 상태·후속 사건·회고에 실제로 반영됩니다.

## 실행

```bash
npm install
npm run dev        # 개발 서버 (http://localhost:5173)
npm run build      # dist/ 에 정적 파일 생성 (오디오 매니페스트 갱신 + 타입 검사 포함)
npm run preview    # 빌드 결과 미리보기
```

`dist/` 폴더는 외부 CDN·폰트·이미지 없이 동작하는 정적 파일입니다(상대 경로 빌드). 사내 웹서버 하위 경로에 그대로 올려도 됩니다. `file://`로 직접 여는 것은 브라우저 모듈 정책 때문에 권장하지 않습니다 — 간단한 정적 서버(`npm run preview` 등)로 여세요.

## 검증

```bash
npm test           # 로직 단위 테스트: 4,000+ 선택 경로 시뮬레이션 + 개별 규칙 10개
npm run build && npm run e2e   # 브라우저 종단 테스트 (Playwright + Chromium, 67개 항목)
```

`npm run e2e`는 Chromium 실행 파일을 `/opt/pw-browsers/chromium`에서 찾습니다. 다른 위치라면 `CHROME=/path/to/chrome npm run e2e`. 결과 스크린샷은 `tests/screens/`에 저장됩니다(커밋 제외). 검증 결과는 [docs/VERIFICATION.md](docs/VERIFICATION.md).

## 자원

- **작업 여유 18칸**: 게임 속 업무 비용(실제 시간 아님). 모자라면 0에서 멈추고 초과분이 ‘일정 지연’으로 기록되며, 진행은 막히지 않습니다.
- **AI 이용권 100점**: 입력 분량·생성·재작업을 나타내는 가상 단위(실제 토큰 요금 아님). 모자라면 부족분 8점당 여유 1칸으로 사람이 직접 처리합니다.
- 모든 선택지 옆에 예상 비용과 알려진 조건이 먼저 표시되고, 부족할 경우 경고가 붙습니다.

## 조작

- **탐색 화면**: 방향키/WASD로 이동, 바닥·사람 클릭으로도 이동, 화면 방향 패드(터치). 상단에 번호 순서(① 누구 → ② 누구 → ③ 목표 지점)가 표시되고, 지금 가야 할 사람 발밑에 링과 ‘!’, 윤진 옆에 방향 화살표가 나옵니다. 가까이 가면 대사가 음성·말풍선으로 나오고 Space로 다시 듣기. 순서를 다 마친 뒤 목표 지점(내 자리 PC 등)에 가면 업무 화면으로 확대 전환됩니다. ‘대화 듣고 바로 가기’ 버튼으로 이동 없이 진행할 수도 있습니다.
- **대사 다시 보기**: 대화창의 ◀ 이전(또는 ← 키)으로 이 장면에서 지나간 대사를 한 줄씩 다시 볼 수 있습니다.
- **선택 다시 하기**: 선택을 확정한 뒤 PC 창 위쪽 ↩ 선택 다시 하기를 누르면, 그 선택 직전으로 돌아가고 쓴 작업 여유·AI 이용권도 돌려받습니다(현재 사건 안에서만).
- **업무 화면**: 마우스 클릭 중심. 사건 ①의 업무 카드는 드래그하거나 카드 안 버튼으로 배치.
- 키보드: `Tab` 선택지 이동, `Enter/Space`(버튼 밖) 다음 대사, `R` 다시 듣기, `S` 건너뛰기, `M` 음성 켜기/끄기, `Esc` 창 닫기.
- 왼쪽 팀원을 누르면 직급·성별·말투·강점·현재 의견을 볼 수 있습니다.
- 1366×768에서 3열(메신저/업무/파일함). 1200px 이하에서는 파일함이, 860px 이하에서는 메신저도 서랍으로 접힙니다.
- 진행 상태는 브라우저 `localStorage`에 저장되어 새로고침 후 **이어하기**가 됩니다. **처음부터 다시**는 저장 상태를 지웁니다.

## 음성

자세한 내용: [docs/VOICE.md](docs/VOICE.md)

- 재생 우선순위: 대사별 음성 파일 → 브라우저 한국어 TTS → 자막
- 시작 화면 **🎙 자연스러운 음성으로 시작**: Edge(Microsoft SunHi·InJoon 등 Natural 음성)·Chrome(Google 음성)의 온라인 신경망 음성을 우선 사용합니다. 사람 목소리에 훨씬 가깝지만 대사 텍스트가 브라우저 제조사의 음성 서비스로 전송되므로, 사내망 기본(🔊 소리 켜고 시작)은 로컬 음성만 씁니다. **사람 같은 음성을 원하면 Microsoft Edge에서 이 버튼으로 시작하세요.**
- BGM은 118BPM 경쾌한 오피스 팝(드럼·베이스·멜로디)을 Web Audio로 합성합니다.
- **현재 음성 파일은 0개(전부 미제작)**. 브라우저 TTS는 캐릭터의 성별 음색과 광주·경상도 억양을 정확히 표현하지 못하며, 7명이 서로 다른 목소리를 낸다고 보장하지 않습니다. 설정 화면에 실제 적용 음성이 표시됩니다.
- 시작 화면의 ‘소리 켜고 시작 / 자막으로 시작’ 클릭 안에서 오디오를 초기화합니다. BGM·효과음은 Web Audio로 합성(외부 파일 없음)하고 대사 중에는 BGM을 줄입니다.

## 프로젝트 구조

```
src/
  data/
    characters.ts   캐릭터 7명: 이름·직급·성별·말투·성향·강점·장면별 의견·아바타·음성 연출
    dialogue.json   모든 대사 (id, sceneId, speakerId, text, expression, condition, nextId)
    options.ts      선택지·비용·알려진 조건 (게임 균형 수치)
    followups.ts    누적 결과 후속 사건: 발생 조건·원인 설명·대응 선택지
    retro.ts        회고 규칙(선택 기록 → 문장), 토의 질문
    files.ts        산출물 미리보기 내용 (가상 데이터)
  logic/game.ts     상태 모델과 모든 상태 전이 (DOM 없음, 단위 테스트 대상)
  audio/voice.ts    음성 파일 → TTS → 자막, 음성 배정, 겹침 방지
  audio/sound.ts    BGM·효과음 (Web Audio 합성)
  ui/               화면 틀, 대화 상자, 아바타(SVG), 저장소
  scenes/           장면별 화면
scripts/
  dialogue.csv      음성 제작용 전체 대본 (자동 생성, audioStatus 포함)
  voice-mapping.csv 캐릭터별 음성 연출·폴더·대사 수
  build-*.mjs       위 파일과 오디오 매니페스트 생성기
public/audio/<speakerId>/  음성 파일 위치 (현재 비어 있음)
tests/              로직 단위 테스트, 브라우저 종단 테스트
```

## 안전·개인정보

- 외부 AI 호출, 실제 사내 시스템/API/DB/원드라이브 연동, 실제 업로드·네트워크 전송이 없습니다. ‘사내 승인 공유함’, ‘승인 설문 도구’, ‘연계 지원 요청’은 승인 상태를 포함한 시뮬레이션입니다.
- 명단·연락처·키 문자열은 모두 가상 데이터입니다. 외부 도구는 ‘사용 불가’로만 표시하고 우회 방법을 제공하지 않습니다.
- 회고 내려받기는 브라우저 안에서 파일을 만들 뿐 어디로도 전송하지 않습니다.
- 캐릭터 아바타는 코드로 그린 일러스트이며 실제 인물을 묘사하지 않습니다.
